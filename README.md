# 매출연동 임대차 (RevenueLease)

**2026 AI Blockchain Challenge in Daegu** 출품작 · 공모분야 ❸ 소상공인·골목상권 디지털 금융 (❺ 병기)

임대료를 **기본료 + 매출 연동분**으로 나누고, 산정 공식을 스마트컨트랙트에 고정한다.
임차인의 결제 데이터가 컨트랙트로 직접 들어와 임대료가 자동 산정·정산된다.

## 왜 대구인가

**대구 소규모 상가 공실률 9.1% — 17개 시도 중 1위.** 동성로 23.3%, 서문시장·청라언덕 34% 이상.
상업용 부동산 투자수익률은 0.32%로 전국 평균의 절반이다.

그런데 임대료는 내려가지 않는다. **임대인이 호가를 낮추면 담보가치가 함께 떨어지기 때문**이다.
임차인은 매출을 모르는 상권에 고정 월세를 걸 수 없다. 둘 다 0원을 택하고 있다.

매출연동 임대차는 백화점에서 수십 년째 쓰는 방식이다. 골목상권에 없는 이유는 하나 —
**매출을 서로 못 믿기 때문**이다. 이 저장소는 그 신뢰 기반을 만드는 코드다.

## 왜 블록체인인가

| 조건 | 이 설계에서 |
|---|---|
| 서로 신뢰하지 않는 다자가 같은 기록을 봐야 한다 | 임대인은 임차인 장부를 믿을 이유가 없다 |
| 사후 감사가 아니라 사전 강제가 필요하다 | 산정 공식이 코드에 있어 사후에 **어느 쪽도 바꿀 수 없다** (변경 함수가 ABI에 없음) |
| 제3자가 원본 없이 검증해야 한다 | 분쟁 시 법원·중개사가 원본 장부 없이 이력을 검증한다 |

DB로 만들면 "그 DB를 왜 믿나"로 되돌아온다.

## 실행

```bash
npm install
npm test          # 컨트랙트 테스트 10개
npm run sim       # 12개월 정산 시뮬레이션 (콘솔)
npm run market    # 상권 분석 (data/raw/ 에 CSV를 넣은 뒤)

# 화면까지 — 터미널 3개
npm run chain     # 1) 로컬 체인
npm run deploy    # 2) 배포 + 조건 활성화 + web/src/deployed.json 갱신
cd web && npm install && npm run dev   # 3) http://localhost:5173
```

`npm run deploy`는 반드시 `npm run chain` 이후에. 체인을 다시 켤 때마다 재배포가 필요하다.

## 컨트랙트 설계 요지

- **조건은 양측 서명으로 한 번만 확정된다.** `activate()`가 임대인·임차인 서명을 검증하고, 조건 변경 함수는 존재하지 않는다.
- **매출은 결제 게이트웨이(은행)만 게시한다.** 임차인 자가신고가 아니다.
- **임대료 = clamp(기본료 + 매출×연동률, 하한, 상한).** 하한은 임대인을, 상한은 임차인을 보호한다.
- **이의가 걸리면 정산이 멈추고 2-of-2 동의로만 풀린다.**
- **예치금이 모자라면 받은 만큼만 지급하고 미납분을 온체인에 기록한다.**

## 12개월 시뮬레이션 결과

동성로 15평 매장 가정 · 기본료 80만 + 매출 8% · 하한 150만 · 상한 350만 · 고정 월세 비교군 250만

| | 임대인 연간 수취 |
|---|---|
| 공실 유지 (현재) | **0원** |
| 매출연동 | **26,960,000원** (고정 월세의 89.9%) |
| 고정 월세 250만 | 30,000,000원 (임차인이 들어와야 성립) |

임차인 최악의 달 부담률: 고정 25.0% → **연동 16.0%**. 진입 결정을 바꾸는 숫자다.

## 아직 없는 것

- **결제 게이트웨이는 목업.** `gateway` 주소로 추상화만 되어 있고 실제 카드 매출 연동은 불가.
  제안서에 "iM뱅크 가맹점 결제 인프라 연동 전제"로 명시할 것.
- **실데이터 미연결.** 분석 스크립트는 준비돼 있다 — `data/raw/` 에 상가정보 분기 스냅샷 CSV를 2개 이상 넣고
  `npm run market` 을 돌리면 대구 업종별 소멸률과 권장 연동률이 `web/public/market.json` 으로 나온다.
  CSV 다운로드에 data.go.kr 로그인이 필요해 수동으로 받아야 한다. `scripts/analyze/README.md` 참조.
- **현금 매출 누락은 구조적으로 못 푼다.** "카드·간편결제 비중 90% 이상 업종부터"로 범위를 한정할 것.

## 주의

프로토타입에서 **1 wei = 1 원**으로 취급한다. 실서비스에서는 원화 스테이블 토큰 또는 은행 원장 연동으로 대체된다.
`web/src/lease.js`의 개인키는 **하드햇 기본 테스트 계정으로 공개된 값**이다. 실제 자산이 있는 네트워크에 절대 사용하지 말 것.
