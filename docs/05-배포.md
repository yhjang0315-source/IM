# 공개 배포 (Render)

심사위원이 아무것도 설치하지 않고 URL 하나로 들어와 만질 수 있어야 한다.
그러려면 두 가지가 각각 공개되어야 한다.

| | 어디에 | 왜 |
|---|---|---|
| 컨트랙트 | Kaia Kairos 테스트넷 | 브라우저가 부를 체인이 있어야 한다. 로컬 체인은 방문자에게 존재하지 않는다 |
| 화면 | Render 정적 사이트 | 번들만 있으면 되고, 서버가 없으니 무료 플랜의 슬립으로 시연이 끊기지 않는다 |

**순서가 중요하다.** 화면은 `deployed.json` 안의 컨트랙트 주소를 보고 움직인다.
체인 배포가 먼저고, 그 결과물을 Render 에 넘긴다.

---

## 1. 체인에 올린다

```bash
npm run keys:new              # 데모 전용 계정 4개 → 출력을 .env 에 넣는다 (이미 했으면 건너뛴다)
```

첫 계정(LANDLORD) 주소로 <https://faucet.kaia.io> 에서 테스트 KAIA 를 받는다.
**이 단계는 사람이 해야 한다** — faucet 이 CAPTCHA 로 막혀 있다.
나머지 세 계정의 가스는 배포 스크립트가 이 계정에서 나눠준다.

```bash
npm run deploy:kairos         # 배포 + 가스 분배 + web/src/deployed.json 갱신
```

`web/src/deployed.json` 의 `network` 가 `kairos` 로 바뀌었는지 확인한다.
`localhost` 인 채로 배포하면 방문자 브라우저가 자기 PC 의 8545 포트를 부르다 실패한다.

## 2. 설정 파일을 Render 에 넘긴다

`web/src/deployed.json` 은 저장소에 없다. 데모 서명 키가 들어 있어 `.gitignore` 에 있다.
그런데 화면은 이 파일 없이는 빌드조차 되지 않는다(`lease.js` 가 import 한다).
그래서 파일 대신 **값으로** 넘긴다.

Render 대시보드 → 서비스 → **Environment** → **Add Environment Variable**

| Key | Value |
|---|---|
| `DEPLOYED_JSON` | `web/src/deployed.json` 파일 내용 전체를 붙여넣는다 |

`scripts/prepare-web-config.js` 가 빌드 시작 때 이 값을 파일로 되돌린다.
찾는 순서는 ① 이미 있는 파일 ② `DEPLOYED_JSON` ③ 저장소 뿌리의 `deployed.json`(Secret File).
셋 다 없으면 빌드를 세운다 — 빈 화면이 배포되는 것보다 낫다.

> 이 키들이 공개 번들에 들어가는 것은 **의도된 것이다.** 심사위원이 지갑 설치 없이
> 임대인·임차인·게이트웨이를 오가며 서명해 보게 하려면 다른 방법이 없다.
> 테스트넷 전용이고 실제 자산은 절대 넣지 않는다. 실제 서비스에서는 은행 앱 내장 키나
> 서버 서명으로 대체된다 — 이 점은 발표에서 먼저 말하는 편이 낫다.

## 3. Render 에 연결한다

<https://dashboard.render.com> → **New** → **Blueprint** → 이 저장소(`yhjang0315-source/IM`) 선택.

뿌리의 `render.yaml` 을 읽어 서비스가 자동으로 잡힌다. 대시보드에서 직접 만들 때는:

| 항목 | 값 |
|---|---|
| Type | Static Site |
| Build Command | `npm ci --prefix web && node scripts/prepare-web-config.js && npm --prefix web run build` |
| Publish Directory | `web/dist` |
| Environment Variable | `BASE` = `/` , `DEPLOYED_JSON` = (2번의 내용) |

뿌리의 hardhat 은 설치하지 않는다. 화면 빌드에 필요 없고 설치만 오래 걸린다.

이후 `main` 에 푸시할 때마다 자동 재배포된다.
**컨트랙트를 다시 배포하면 `DEPLOYED_JSON` 을 새 값으로 바꾸고 수동 재배포해야 한다** —
저장소는 그대로라 Render 는 바뀐 줄 모른다.

## 4. 확인한다

배포된 URL 에서:

- 헤더에 컨트랙트 주소가 뜨고 그 아래 상태가 `미확정` 또는 확정된 조건으로 나온다
- 역할 전환 버튼(임대인/임차인/게이트웨이)이 동작한다
- 트랜잭션을 하나 보내고 <https://kairos.kaiascan.io> 에서 같은 해시가 보인다

첫 화면이 계속 로딩이면 브라우저 콘솔을 본다. `127.0.0.1:8545` 를 부르고 있으면
`DEPLOYED_JSON` 이 로컬 설정인 것이다.

## GitHub Pages 와의 차이

`npm run build:pages` + `npm run publish:pages` 로 `gh-pages` 브랜치에 올리는 경로도 남아 있다.
둘 다 정적 호스팅이라 결과는 같고, 차이는 이 정도다.

| | Render | GitHub Pages |
|---|---|---|
| base 경로 | `/` (도메인 뿌리) | `/IM/` (저장소 하위) |
| 배포 | 푸시하면 자동 | `publish:pages` 를 직접 실행 |
| 설정 파일 | 대시보드 환경변수 | 로컬 빌드에 이미 들어감 |
| 커스텀 도메인·HTTPS | 있음 | 있음 |

Render 쪽이 URL 이 짧고 재배포가 자동이라 제출용으로 낫다.
Pages 는 Render 가 막힐 때의 대비책으로 남긴다.
