# 발표 대비

본선 15분 = 발표 10분 + 질의응답 5분.

## 반드시 나올 질문 4개

### 1. "임대인이 매출 연동에 왜 동의하나?"

지금 받고 있는 게 **0원**이다. 공실률 전국 1위, 투자수익률 0.32%.
그리고 임대료를 **내리는 게 아니라 연동하는 것**이라 호가와 담보평가 기준을 지킬 수 있다.
호가를 낮추면 담보가치가 함께 떨어지는데, 연동은 그 문제를 피해 간다 — 이게 핵심 설득 포인트다.

시뮬레이션 근거: 12개월 누적 임대인 수취 2,696만원, 고정 월세 3,000만원 대비 **89.9%**.

### 2. "매출을 속이면?"

임차인이 입력하는 구조가 아니다. **결제 게이트웨이(은행)가 컨트랙트에 직접 게시**하며,
컨트랙트가 그 외 주소의 게시를 거부한다(테스트로 검증됨).

현금 매출 누락은 **완전히 못 푼다.** 숨기지 말고 인정하고,
"카드·간편결제 비중 90% 이상 업종부터"로 범위를 한정한다고 답한다.

### 3. "이미 백화점이 하지 않나?"

맞다 — 그래서 검증된 방식이다. 백화점은 매출 데이터를 직접 쥐고 있어서 가능했고,
**골목상권에는 그 신뢰 기반이 없어서 못 했다.** 그 기반을 만드는 것이 이 제안이다.

### 4. "연동률을 왜 8%로 잡았나?"

**협상으로 정한 값이 아니라 그 업종이 실제로 얼마나 사라지는가에서 나온다.**
소상공인시장진흥공단 상가(상권)정보 대구 스냅샷 3개(2025-06-30 / 2025-12-31 / 2026-03-31)를
비교해 업종별 소멸률을 냈다. 표본 30개 이상 업종 211종, 상권×업종 607조합.

| | 값 |
|---|---|
| 카페 표본 | 5,363개 |
| 9개월 소멸률 | 12.8% |
| 연 환산 잔존율 | 83.3% |
| 권장 기본료 / 연동 | 31% / 69% |
| 이 계약의 기본료 비중 | 32% (80만 / 시세 250만) |

권장치 31%와 실제 32%가 거의 일치한다 — 조건을 먼저 정하고 데이터를 끼워 맞춘 게 아니다.
연동률 8%는 **월매출 2,125만원에서 연동 임대료가 시세 250만원과 같아지도록** 잡은 값이다.

눈금도 임의로 두지 않았다. 업종별 연 잔존율의 5~95 백분위(80.7%~98.0%)를
기본료 비중 25~65%로 매핑한다. 구간을 상수로 박으면 실제 분포와 어긋나 상·하한에 업종이 뭉친다.

**화면에서 직접 보여줄 것** — "업종 근거" 탭에서 업종을 바꾸면 소멸률과 권장 연동분이 즉시 따라온다.
같은 카페라도 상권별로 갈린다(동성로가 있는 중구 성내1동 224개 · 소멸률 10.7%).

한계는 먼저 밝힌다: 공식 폐업 플래그가 없어 **직전 스냅샷의 상가업소번호가 사라진 것을 소멸로 추정**했다.
이전·상호변경·휴업이 섞여 있다.

## 예비 질문

- **"상가임대차보호법 차임 증감 조항과 충돌하지 않나?"** — `docs/04-법적-검토.md` 참조.
  요지: 제11조의 5% 상한은 **일방의 증감청구에만** 적용되고 합의로 정한 차임에는 적용되지 않는다(대법원 2013다80481).
  대규모유통업법 제2조의2가 "상품 매출액에 연동되는 임차료"를 명문화해 적법한 거래형태로 전제하고 있다.
- **"블록체인 없이 은행 DB로 하면 안 되나?"** — 임대인이 그 DB를 믿을 이유가 없다.
  산정 공식과 확정 이력이 사후에 바뀔 수 없어야 하는데, DB는 운영기관이 언제든 바꿀 수 있다.
- **"실제 결제망에 붙나?"** — 안 붙는다. 시뮬레이션이며 "iM뱅크 가맹점 결제 인프라 연동 전제"임을 먼저 밝힌다.
- **"미납이 쌓이면?"** — 예치가 임대료에 모자라면 받은 만큼만 지급하고 차액을 미납으로 기록한다.
  `repay()` 로 부분 상환할 수 있고, **계약이 끝난 뒤에도 채무로 남는다.** 화면의 임차인 탭에 상환 버튼이 있다.
- **"매출 원본을 체인에 올리면 개인정보 아닌가?"** — 올리지 않는다. 게이트웨이는 정산 원본 파일의 **해시만** 기록한다(`postRevenue(period, revenue, proof)`).
  원본은 은행이 보관하고, 분쟁 시 원본을 다시 해시해 대조하면 위변조가 드러난다.
- **"이의를 무기한 걸 수 있나?"** — 게시 후 **7일** 안에만 가능하다(`DISPUTE_WINDOW`). 기한이 지나면 컨트랙트가 거부한다.
- **"계약 중간에 나가면 예치금은?"** — 처리 중인 달(게시됨·이의)이 남아 있으면 종료 자체가 막힌다.
  종료되면 정산되지 않은 예치금은 임차인에게 반환하고, **남은 미납분은 보증금에서 회수**한 뒤 나머지 보증금을 돌려준다.
  보증금으로도 모자라면 그만큼은 채무로 남고 `repay()` 로 갚는다.
- **"합의가 끝까지 안 되면?"** — 이것이 2-of-2 방식의 유일한 약점이고, 그래서 **조정인**을 두었다.
  다만 세 가지 제약이 있다. (1) 조정인은 **양측이 계약 체결 시 함께 서명**해 지정한 사람만 될 수 있다.
  (2) 이의가 걸린 뒤 **14일**이 지나야 개입할 수 있다. (3) **은행(게이트웨이)은 조정인이 될 수 없다** —
  매출을 게시한 쪽이 분쟁까지 결정하면 안 되기 때문이다. 조정인을 지정하지 않은 계약은 오직 합의로만 풀린다.
  즉 "제3자 개입"을 넣으면서도 **양측이 사전에 동의한 범위 안에서만** 작동한다.

## 시연 시나리오 (5분 이내)

앱은 미체결 상태에서 시작한다(`npm run deploy`). 역할 전환 버튼으로 "지금 나는 누구인가"를 바꿔 가며 진행한다.

1. **계약 탭, 임대인** — 업종 "카페", 상권 "중구 성내1동" 선택 → 실데이터 권장값이 뜬다(표본 224개, 연 잔존 86%, 기본료 37% / 연동 63%) → "권장값 적용" → 기본료 93만 · 연동 7.8%가 채워진다 → 12개월 미리보기 → **임대인 서명**
2. **임차인으로 전환** — 조건이 잠긴 채로 보인다. 반려 버튼도 있다 → **임차인 서명**
3. **체인에 확정** — 토스트에 블록 번호와 tx 해시. 헤더가 "확정 · 변경 불가"로 바뀌고 기간이 달력으로 붙는다. 활동 탭에 `Activated` 첫 줄
4. **임차인 탭** — 다음 달 매출 슬라이더로 임대료를 미리 보고 **예치**. 슬라이더를 아래로 내리면 "하한 적용" 태그
5. **게이트웨이로 전환, 게이트웨이 탭** — 확정 매출 **게시**. 임차인·임대인이 게시하려 하면 컨트랙트가 거부한다(역할 버튼을 바꿔 보여줘도 됨)
6. **임대인으로 전환 → 이의 제기** — 정산이 멈춘다. 게이트웨이 역할로 가면 할 수 있는 게 없다 → **임차인으로 전환 → 동의** → 매출·임대료가 재산정되고, 예치가 모자라면 "부족 → 미납으로 기록됨" 경고
7. **게이트웨이 → 정산** — 원장에 지급·미납이 찍히고, 임대인 탭에 미납 누계, 활동 탭에 `Settled`
8. 남은 달은 게이트웨이의 **"시연: 예치 → 게시 → 정산 한 번에"**로 빠르게 채운다 (세 역할 키를 한 번에 쓰는 시연 전용)
9. **미납 상환** — 일부러 적게 예치한 달을 정산하면 임차인 탭에 "미납 상환"이 뜬다. 전액 상환 → 임대인에게 바로 지급된다
10. **업종 근거 탭** — "이 숫자 어디서 나왔냐"에 대한 답. 업종을 바꾸면 소멸률과 권장 연동분이 따라온다
11. **명세서 탭** — 당사자·확정 조건·산정식·분쟁 규칙·월별 정산이 한 장에. **인쇄 버튼으로 PDF 저장**까지 보여주면 좋다
12. **활동 탭** — 지금까지 한 모든 일이 블록 번호·tx 해시와 함께 남아 있다. "DB로 하면 안 되냐"에 대한 화면 답변

**여유가 있으면 보여줄 것**

- 게시만 하고 정산하지 않은 달을 남긴 채 계약 종료를 눌러 본다. "아직 처리 중인 달이 있습니다"로 막힌다.
  돈이 묶인 채 계약이 끝나지 않는다는 것을 한 번에 보여주는 장면이다.
- **조정인 시연** — 이의를 걸어 교착을 만든 뒤 `npm run demo:ff` 로 체인 시간을 15일 앞으로 돌린다.
  조정인 역할로 바꾸면 그때서야 "조정안으로 확정" 버튼이 나타난다. 기한 전에는 버튼 대신 개시 가능일이 표시된다.
- **보증금 회수** — 미납을 남긴 채 계약을 종료하면 보증금에서 미납분을 회수하고 나머지가 반환되는 것이
  활동 탭 한 줄로 찍힌다.

체결 화면을 건너뛰고 정산만 보여줄 땐 `npm run deploy:active`.
